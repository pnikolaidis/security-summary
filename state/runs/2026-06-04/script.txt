Aiden Iyer reporting in for Thursday.

Today we have five stories that security teams should act on immediately. Two carry active exploitation or a live public exploit. One touches operational technology. One is a milestone for internet infrastructure. Let's get into it.

Story one. CISA has added a critical Magento vulnerability to its Known Exploited Vulnerabilities catalog. The flaw is CVE-2026-45247, and it scores a nine point eight on the CVSS scale. It lives in the Mirasvit Cache Warmer extension for Magento, which is a popular full-page caching plugin used by e-commerce stores worldwide. The vulnerability is a deserialization flaw, meaning an attacker can send crafted data to the server and trigger remote code execution without any kind of login. CISA's addition to the catalog confirms active exploitation in the wild. Federal agencies are on a mandatory patching clock. Why it matters: e-commerce infrastructure is inherently internet-facing, and an exploit that is already in active use means the window to act before you are targeted is closing fast. If your organization runs the Mirasvit Cache Warmer, this is a drop-everything situation.

Story two. A critical remote code execution vulnerability has been published for OpenStack Mistral, the workflow automation service used across many cloud deployments. The CVE is 2026-41283, and it rates a nine point nine — one of the highest scores possible. When the Mistral workflow API is reachable from the network, attackers can use built-in endpoints to execute arbitrary code on the server. Worse, the CVSS scope change flag means successful exploitation spills beyond Mistral itself and can expose service credentials for the entire OpenStack environment. If you are running OpenStack Mistral and the API is reachable from any network segment you do not fully control, restricting access at the network level is a critical first step while you plan a patch. Cloud operators relying on Mistral for workflow automation should treat this as high-priority remediation.

Story three. ABB has disclosed four vulnerabilities in its T-MAC Plus industrial networking module. The most severe, CVE-2025-14771, rates nine point nine and describes files and directories on the device as accessible to external parties. In plain terms, an unauthenticated external attacker can read configuration data and sensitive operational files directly. A companion vulnerability, CVE-2025-14772, rates eight point eight and allows authorization bypass through a user-controlled key, removing the need for valid credentials entirely. Two additional issues cover cross-site scripting and incorrect authorization at lower but still significant scores. Industrial facilities and utilities running T-MAC Plus modules in environments reachable from untrusted networks should prioritize patching or network segmentation immediately. These are precisely the types of vulnerabilities that threat actors targeting operational technology environments seek out.

Story four. Let's Encrypt announced production support for post-quantum hybrid certificates this week, and it is a significant milestone for the web. They are now issuing certificates that combine classical cryptography with ML-KEM, one of the new NIST post-quantum standards, in a hybrid design. This means that even if a future quantum computer eventually breaks classical encryption, the post-quantum component protects the connection independently. Let's Encrypt is the largest certificate authority in the world by volume, so this is not a research prototype. It is a genuine shift in web infrastructure happening right now, affecting a large fraction of all HTTPS connections on the internet. The security community took notice: the Hacker News post drew nearly two hundred and seventy points and one hundred and fifty comments from practitioners working through the tradeoffs. The known costs are larger certificate sizes, slightly longer TLS handshakes, and partial client support. The direction is clear, and if you manage web infrastructure, now is the time to begin testing compatibility.

Story five. A security researcher disclosed a one-click vulnerability in Visual Studio Code that can steal a developer's full GitHub OAuth token and published the proof-of-concept without first notifying Microsoft. The vulnerability lives in the GitHub dot dev feature of VS Code. A single click on a carefully crafted link is all it takes. No additional user action, no login prompt. The stolen token grants full read and write access to every repository the victim has access to, including private ones. A working exploit is now publicly available, which means any developer who opens untrusted links inside VS Code is at risk right now, before a patch exists. The disclosure without vendor notice will likely reignite the coordinated disclosure debate that surfaced last week when a researcher's GitHub account was removed after publishing unpatched Windows exploits. For defenders, make sure developers on your team are aware of this and treat VS Code links from untrusted sources with the same caution as email attachments.

That's your digest for Thursday, the fourth of June. Five stories: two with active or imminent exploitation, one industrial OT cluster, one post-quantum infrastructure milestone, and one developer toolchain zero-day with a live exploit. Stay safe out there.
